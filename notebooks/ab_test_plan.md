# План A/B-тестирования

## Цель
Сравнить две версии модели прогнозирования дефолта по кредитным картам:
- **v1** — базовая модель (Random Forest на всех 23 признаках)
- **v2** — улучшенная модель (9 признаков + feature engineering + балансировка классов)

## Гипотезы
### Нулевая гипотеза (H₀)
Новая модель v2 НЕ лучше текущей модели v1 по метрике F1-score.
### Альтернативная гипотеза (H₁)
Новая модель v2 ЛУЧШЕ текущей модели v1 по метрике F1-score.

## Разделение трафика
- **Группа A (контроль):** 50% трафика → модель v1
- **Группа B (тест):** 50% трафика → модель v2

## Длительность теста
- **Минимальная длительность:** 30 дней
- **Необходимый размер выборки:** ~30 000 запросов на группу

## Метрики

### Основная метрика
**F1-score** для класса дефолта

### Дополнительные метрики
- **Recall** — доля найденных реальных дефолтов
- **Precision** — доля верных предсказаний дефолта

### Бизнес-метрики
1. **Ожидаемое снижение потерь** = (Recall_v2 - Recall_v1) × Средний кредит × Частота дефолтов
2. **ROI** = (Экономия - Затраты) / Затраты

## Статистический анализ

- **Метод:** Z-тест для пропорций
- **Уровень значимости:** α = 0.05
- **Мощность теста:** 1-β = 0.80
- **Доверительный интервал:** 95%

## Критерий успеха

Новая модель v2 считается успешной, если:
1. p-value ≤ 0.05
2. F1-score_v2 > F1-score_v1
3. Recall_v2 не хуже Recall_v1

## Ожидаемые результаты

| Метрика | v1 | v2 | Изменение |
|---------|----|----|-----------|
| F1-score | 0.4592 | 0.5310 | +15.6% |
| Recall | 0.3519 | 0.5607 | +59.3% |
| Precision | 0.6605 | 0.5044 | -23.6% |

## Связь с архитектурой

Для поддержки A/B-теста сервис должен:
1. Маршрутизировать запросы между v1 и v2
2. Логировать версию модели в `logs/api_logs.json`
3. Собирать метрики для анализа

## Вывод

A/B-тест позволит объективно оценить, улучшает ли модель v2 бизнес-показатели по сравнению с v1.
